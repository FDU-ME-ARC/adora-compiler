# Emit Bug Report — 2026-05-18

## 现象

`cgra-mapper` 在 mapping 成功后，进入代码生成（emit）阶段时崩溃，`rc=134`（SIGABRT）。

**不影响 mapping 结果**：II / MaxLat / placement 数据已在 REPORT.md 中记录，emit crash 发生在这之后。

---

## 错误位置

### 触发方式 1：`--output-type=c`（触发 EmitCGRACall）

```

bool {anonymous}::CGRVOpEmitter::visitOp(mlir::affine::AffineStoreOp):
Assertion `op.getMemref().getType().cast<MemRefType>().getShape().size() == 0' failed.
```

### 触发方式 2：`--output-type=sdk`（触发 EmitVitisSDK）

```
cgra-mapper: adora-compiler/mapper/src/emit/EmitVitisSDK.cpp:769
bool {anonymous}::VitisSDKOpEmitter::visitOp(mlir::affine::AffineStoreOp):
Assertion `op.getMemref().getType().cast<MemRefType>().getShape().size() == 0' failed.
```

---

## 根本原因

`EmitVitisSDK.cpp:769` / `EmitCGRACall.cpp:760`：

```cpp
bool visitOp(::mlir::affine::AffineStoreOp op) {
    // ...
    assert(op.getMemref().getType().cast<MemRefType>().getShape().size() == 0);
    // ↑ 断言 memref 是 0 维（scalar），但实际是多维 memref（如 memref<24xi32>）
    std::string memref = _cgracallemitter->lookupName(op.getMemref());
    indent() << memref << " = " << value << ";\n";
}
```

**断言含义**：emitter 预期 `AffineStoreOp` 的 memref 是 0 维 scalar。

**实际输入**：bicg / gemm 等 kernel 的 AffineStoreOp 写入的是 `memref<24xi32>` 这样的 1D array（来自 ADORA BlockStore 之后的 affine store）。

---

## 触发 kernel

所有带 array output 的 kernel 均触发：
- `bicg`（`memref<24xi32>`）
- `gemm`（`memref<64xi32>`）
- `gesummv`、`jacobi-2d`、`mvt`、`2mm` 等

---

## 临时绕开方案（已采用）

`run_mapper_with_llm.sh` 已改为 `--output-type=c`，emit 仍 crash（rc=134），
但 mapping 已完成，**REPORT.md 中的 II / MaxLat / LLM decisions 数据完整有效**，
可正常用于 E1 ablation 实验。

---

## 修复方向

`EmitVitisSDK.cpp:769` / `EmitCGRACall.cpp:760` 两处逻辑相同：

```cpp
// 修复前：断言必须是 scalar memref
assert(op.getMemref().getType().cast<MemRefType>().getShape().size() == 0);

// 修复后：支持多维 memref，生成带下标的 C 语句
auto shape = op.getMemref().getType().cast<MemRefType>().getShape();
if (shape.size() == 0) {
    // scalar: direct assignment
    indent() << memref << " = " << value << ";\n";
} else {
    // array: emit with index expression from op.getMapOperands()
    // TODO: generate correct index string
    indent() << memref << "[...] = " << value << ";\n";
}
```
